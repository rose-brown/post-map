# 작업 로그 — 2026-09-29 (지하철 레이어)

## 요약

사용자 요청: 지하철 역·호선을 지도 레이어로, 역 500m 이내 단지와 기준역까지 30분·1시간 이내 단지를 거르고 싶다.
앱 코드는 바꾸지 않고 **스크립트가 레이어로 미리 나눴다** (`scripts/transit/`). 설계 `docs/superpowers/specs/2026-09-29-transit-layers-design.md`.

## 사용자 결정

- 기준역은 **선릉·여의도·시청** 고정 (처음 말한 강남역 대신).
- 필터는 앱 UI 가 아니라 **스크립트가 만든 사본 레이어** (TOP9 방식).
- 시간 = **도보 + 지하철 + 환승** (대기 제외).
- 빈 노선을 채울 출처로 **KTDB GTFS 신청** → 2025-03판이 바로 도착해 전 노선을 GTFS 하나로 처리했다.
- 선 모양 = **역을 운행 순서로 직선 연결** (OSM 안 씀).
- 호선별 레이어, 원본 단지에도 속성 부착.

## 구현 중 찾은 것

- **급행 표시 없는 건너뛰기 운행.** 갈래마다 가장 긴 운행만 그리면 5호선 마천지선이 빠지고, 새 구간을 더하는 운행을
  다 그리면 경의중앙(문산→금촌)·경춘(회기→상봉)·수인분당의 건너뛴 현이 선으로 겹친다. "다른 운행에서 a·b 사이에 역이 끼면 현"
  규칙으로 거른다. 순환선 마지막 구간은 그 운행 안에서 이웃이라 걸리지 않는다.
- **직결 운행역은 stop_id 를 공유한다** — 역 도형 id 를 (호선 코드, stop) 으로 만든다.
- **Windows 에서 `npm test` 는 0개로 통과한다** (cmd 가 작은따옴표 glob 을 넘긴다). `node --test tests/*.test.ts` 로 53→55개 통과 확인.
- `scripts/lead50/sb.ts` 의 `ensureLayer` 가 lead50 스키마에 묶여 있어 병합 함수를 인자로 받게 했다 (기본값은 그대로).

## 후속 (같은 날, 사용자 요청)

- **선을 없앴다** — 역을 직선으로 이은 선이 배경지도 선로와 어긋났다. 재실행으로 선 35개 삭제 (앞서 "45" 라고 적은 것은 건너뛴 현을 거르기 전 dry-run 숫자였다).
  건너뛴 현을 거르던 `lineStopOrders` 와 테스트도 지웠다 — 되살린다면 이 로그의 "구현 중 찾은 것" 첫 항목부터 본다.
- **역 점을 절반(3px)으로** — 앱의 `dotRadius` 가 레이어 `style.pointRadius` 를 기본 반지름으로 쓰게 했다 (전에는 상수 6, `pointRadius` 는 안 쓰였다).
  스크립트가 호선 레이어 24개의 `pointRadius` 를 3 으로 맞춘다. 스크린샷 `docs/screenshots/transit-03-stations-only.png`.

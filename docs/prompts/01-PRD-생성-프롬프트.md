위 공통 컨텍스트를 전제로, 이 제품의 **PRD(제품 요구사항 문서)**를 작성해줘.

## 작성 원칙

- 이미 확정된 기술 스택과 불변 규칙은 다시 논의하지 말고 **전제로** 삼아라. 근거를 재서술하지 마라.
- 아직 안 정해진 것은 **결정이 필요한 항목으로 따로 모아** 선택지와 트레이드오프를 제시해라. 임의로 정하고 넘어가지 마라.
- 분량을 채우지 마라. 읽는 사람의 다음 행동을 바꾸지 않는 문장은 빼라.
- 기능 설명은 "무엇을 할 수 있다"가 아니라 **"어떤 입력에 어떤 결과가 나온다"**로 써라.

## 목차

### 1. 제품 정의
- 한 문장 정의, 해결하는 문제, 명시적 비목표(Non-goals)
- 이 제품이 아닌 것 — QGIS 대체가 아니고, 카카오맵 대체도 아니다. 그 경계를 분명히.

### 2. 사용자와 시나리오
- 주요 사용자 유형 2~3개와, 각각의 **구체적 작업 시나리오 1개씩** (클릭 단위로)
- 시나리오는 범용 플랫폼이 실제로 서로 다른 용도를 어떻게 흡수하는지 보여야 한다

### 3. 기능 명세
기능마다 아래 표 형식으로:

| 항목 | 내용 |
|---|---|
| 기능 ID | F-01 |
| 이름 | |
| 입력 | 사용자가 무엇을 하면 |
| 동작 | 시스템이 무엇을 하고 |
| 출력 | 무엇이 보이거나 저장되는가 |
| 예외 | 실패·경계 조건 |
| Phase | 1~4 |

다뤄야 할 기능군:
- 작도: point / line / polygon 생성·선택·이동·삭제, 꼭짓점 편집, 스냅, 구멍(hole)
- 공간연산: 동심원(다중 반경 링), 거리 버퍼(양수/음수), 합집합·교차·차집합, 면적·길이 측정
- 검색: 주소 검색, 장소명 검색, 좌표→주소 역지오코딩
- 경로: 두 지점 간 소요시간·경로 표시 / (후순위) 등시선, 다대다 행렬, 출발시각 기준 도착시각
- 레이어: 내 벡터 레이어 관리, 파일 업로드, 공공데이터 API, 배경 타일·WMS
- 정보 페이지: 속성 스키마 정의, 값 입력, 자유 블록 편집, 템플릿 적용
- 조회: 레이어 테이블 뷰, 속성 필터, 정렬, 지도↔테이블 연동 선택
- 공유·권한 (Phase 3)

### 4. 데이터 모델
- 공통 컨텍스트의 모델을 **ERD 수준으로 구체화**. 필드명·타입·제약·인덱스까지.
- PostGIS 전환을 전제로, 로컬(IndexedDB) 스키마와 서버 스키마의 대응 관계를 표로.
- 속성 스키마의 타입 시스템 정의 — 각 타입의 저장 형태, 입력 UI, 필터 연산자

### 5. 화면 구조
- PC / 모바일 각각의 레이아웃 (텍스트 와이어프레임으로)
- 패널 구성: 지도, 레이어 패널, 정보 페이지 패널, 테이블 뷰, 도구 팔레트
- 모바일에서 무엇이 바텀시트가 되고 무엇이 숨겨지는지

### 6. 비기능 요구
- 성능 목표: 피처 N개에서 팬·줌 프레임, 초기 로딩, 파일 업로드 상한
- 오프라인 동작 범위 (반응형 웹이므로 제한적 — 어디까지 할지)
- 브라우저 지원 범위
- 접근성: 키보드 작도, 색각 고려 레이어 색상

### 7. Phase 계획
- Phase 1~4의 범위, 완료 기준, 각 Phase에서 새로 필요한 외부 키
- Phase 간 마이그레이션 지점 (로컬 → Supabase가 특히)

### 8. 결정이 필요한 항목
아직 안 정해진 것들. 각각 선택지 2~3개와 트레이드오프, 그리고 **언제까지 정해야 하는지(어느 Phase를 막는지)**.
최소한 아래는 포함해라:
- 경로 API 제공자 — **응답 결과를 저장해도 되는지**를 1순위로, 그다음 무료 제공량·경유지 수 비교. (카카오는 로컬 API 결과의 저장을 불허한다는 공식 답변이 있다. 경로 API에도 같은 제약이 걸리는지가 이 제품의 "소요시간을 속성으로 저장" 기능의 성립 여부를 결정한다)
- 등시선을 외부 API로 살지, OSM 기반 라우팅 엔진(Valhalla / OpenRouteService)을 자가호스팅할지
- SHP 파싱을 브라우저에서 할지 서버에서 할지 (인코딩·대용량 문제)
- 대용량 레이어 렌더링 전환 시점 (GeoJSON → PostGIS 벡터타일)

### 9. 리스크
기술·법무·비용 리스크. 특히:
- 국내 지도 API 이용약관 제약 (타사 지도 위 오버레이, 데이터 저장·재배포)
- 공공데이터 API의 가용성·품질 편차
- 무료 쿼터 초과 시 비용 구조

## 출력 형식

마크다운 문서 한 개. 확실하지 않은 사실은 단정하지 말고 `(확인 필요: 출처)` 형태로 표시해라.

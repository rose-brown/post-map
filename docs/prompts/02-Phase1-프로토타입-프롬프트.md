위 공통 컨텍스트를 전제로 **Phase 1**을 구현해줘.

## Phase 1의 목표

실제 지도 위에서 작도하고, 주소를 검색하고, 찍은 도형에 정보 페이지를 붙여 편집하는 것까지.
데이터는 브라우저에만 저장한다. 로그인 없음. 백엔드 없음.

**완료 기준** — 아래가 전부 브라우저에서 실제로 동작해야 한다:

1. VWorld 배경지도가 뜨고 팬·줌·회전이 된다
2. 도구를 골라 point / line / polygon 을 그린다. 그린 도형을 다시 선택·이동·삭제할 수 있다
3. 그린 polygon 의 꼭짓점을 끌어서 모양을 바꿀 수 있다
4. point 를 선택하면 다중 반경 동심원(기본 500m / 1km / 2km, 값 편집 가능)을 그릴 수 있고, 각 링에 반경 라벨이 붙는다
5. 상단 검색창에 주소나 장소명을 넣으면 후보가 뜨고, 고르면 지도가 이동하며 그 자리에 point 가 생긴다
6. 도형을 선택하면 오른쪽(모바일은 바텀시트)에 정보 페이지가 열린다. 제목, 스키마 속성값, 자유 블록을 편집할 수 있다
7. 템플릿을 고르면 스키마 속성과 블록이 한 번에 추가된다
8. 새로고침해도 모든 데이터가 남아 있다
9. 모바일 브라우저(360px 폭)에서 지도 작도와 정보 편집이 모두 가능하다
10. 현재 프로젝트를 GeoJSON(FeatureCollection)으로 내보낼 수 있다

## 구현 범위

### 1. 프로젝트 셋업
- Vite + React + TypeScript (strict), Tailwind CSS
- `maplibre-gl`(v6), `terra-draw`(v1) + `terra-draw-maplibre-gl-adapter`(v1), `@turf/turf`(v7), `proj4`, `zustand`, `dexie`(또는 `idb`)
- 환경변수: `VITE_VWORLD_KEY`(배경지도 타일), `VITE_GEOCODER_KEY`(공공데이터포털 서비스키). `.env.example` 를 만들고 `.env` 는 gitignore
- 지오코더·검색 API 호출은 **Vite dev 프록시(`server.proxy`)를 경유**한다. 브라우저 직접 호출은 CORS와 키 노출 문제가 생길 수 있다. 배경지도 타일만 도메인 등록 방식이므로 브라우저에서 직접 호출하고, 그 이유를 주석으로 남겨라. 프로덕션 빌드에는 프록시가 없으므로 "개발 전용"임을 README에 명시하고 Phase 3에서 Edge Function으로 대체한다는 주석을 남겨라.

### 2. 지도
- VWorld WMTS 래스터 타일을 MapLibre `raster` 소스로 등록. 배경지도 종류(일반/위성/하이브리드) 전환 UI 제공
- VWorld 타일 URL 규격과 도메인 등록 요건은 공식 레퍼런스(vworld.kr)를 확인하고 구현해라. 추측으로 URL을 만들지 마라
- 초기 뷰포트는 서울시청 근방, zoom 12
- 지도 컨트롤: 줌, 현재위치(Geolocation API), 축척바, 좌표 표시

### 3. 작도 (Terra Draw)
- 도구: 선택 / point / line / polygon / 사각형 / 원 / 삭제
- Terra Draw 의 MapLibre 어댑터를 쓰고, 모드 전환은 Zustand 스토어에서 관리
- **선택 모드에서 꼭짓점 편집·도형 이동 활성화** (Terra Draw select 모드의 draggable / editable 옵션 확인)
- 모바일: 도구 팔레트는 하단 가로 스크롤 바. 터치로 작도 가능해야 함. 꼭짓점 핸들은 터치 타깃 44px 이상
- 그리는 중 ESC로 취소, 마지막 점 되돌리기

### 4. 동심원
- 선택된 point(또는 지도 클릭 지점)를 중심으로 반경 배열을 받아 링을 생성
- 기본값 `[500, 1000, 2000]` 미터. UI에서 반경 추가·삭제·수정 가능
- **측지 계산**: `turf.circle(center, radius, { units: 'meters', steps: 64 })` 사용. 픽셀 기반 원 금지
- 각 링은 반투명 채움 + 외곽선, 링마다 반경 라벨(symbol layer)
- 동심원은 별도 Feature 로 저장되며, 중심 point 를 지우면 같이 지워진다(참조 관계 유지)

### 5. 주소·장소 검색

**제공자는 공공데이터포털의 국토교통부 지오코더/검색 API 로 한다.** 이 제품은 검색 결과를 피처로 영구
저장하므로, 응답 저장을 금지하는 제공자를 쓸 수 없다. 카카오 로컬 API는 결과의 저장이 허용되지 않으므로
Phase 1에서 쓰지 마라. (공통 컨텍스트의 "외부 API 결과의 저장 가능 여부" 참조)

- `GeocodingProvider` 인터페이스 정의 후 구현체 하나만 만든다
- **공식 레퍼런스를 먼저 읽어라.** 공공데이터포털의 `국토교통부_지오코더 API`(주소↔좌표)와
  `국토교통부_검색 API`(장소·지명·주소 검색) 상세 페이지, 그리고 vworld.kr 의 Geocoder API 2.0 /
  검색 API 2.0 레퍼런스를 확인해라. **이 프롬프트를 쓴 시점에 vworld.kr 문서를 직접 읽지 못했으므로,
  파라미터명·응답 구조·엔드포인트를 이 문서에서 추론하지 말고 반드시 원문에서 확인해라.**
- 두 경로(포털 발급 vs vworld.kr 직접 발급)가 같은 엔드포인트인지 먼저 확인하고, 다르면 포털 쪽을 쓴다
- 도로명주소와 지번주소는 요청 타입이 갈리는 구조다. 문서에서 정확한 값을 확인한 뒤, 둘 다 시도해서
  결과를 합치고 어느 쪽에서 나온 결과인지 표시해라
- **호출량 관리**: 지오코더는 일 40,000건 제한이다. 역지오코딩 결과를 좌표 기준으로 로컬 캐시하고,
  같은 지점에 대해 반복 호출하지 마라. 검색은 디바운스 300ms

```ts
interface GeocodingProvider {
  readonly id: string
  readonly canPersistResults: boolean   // 응답을 저장해도 되는 제공자인가
  searchAddress(query: string): Promise<GeocodeResult[]>
  searchPlace(query: string, near?: [number, number]): Promise<GeocodeResult[]>
  reverse(lng: number, lat: number): Promise<GeocodeResult | null>
}
interface GeocodeResult {
  id: string
  name: string          // 장소명 또는 도로명주소
  address: string       // 지번주소
  roadAddress?: string
  lng: number
  lat: number
  category?: string
}
```

- 검색창: 디바운스 300ms, 주소·장소 결과를 구분해서 표시, 키보드 위아래 선택
- 결과 선택 → 지도 이동(flyTo) + 해당 좌표에 point Feature 생성 + 정보 페이지 자동 열림
- point 를 새로 찍으면 역지오코딩으로 주소를 자동 채운다(실패해도 작도는 성공해야 함)
- 저장 경로에는 `canPersistResults === true` 인 제공자의 결과만 들어갈 수 있게 해라. false 인 제공자를
  끼웠을 때 컴파일이 깨지거나 런타임에서 명확히 거부되어야 한다

### 6. 정보 페이지
프로토타입(`임장 지도 프로토타입.dc.html`)의 UI 구조를 계승하되, 도메인 하드코딩은 제거한다.

- 상단: 제목 입력, 주소·좌표 표시
- **속성 영역**: 현재 레이어의 스키마 필드가 먼저 나오고, `+ 속성 추가`로 자유 필드를 붙인다
  - 타입별 입력 UI: text / number(단위 표시) / date / select / boolean
  - 숫자 필드는 천단위 구분, 단위 접미사 표시
- **블록 영역**: `text | heading | todo | gallery | files | callout | divider`
  - gallery: 이미지 여러 장. IndexedDB 에 Blob 으로 저장하고 `URL.createObjectURL` 로 표시. **base64 data URL 로 저장하지 마라** (용량 폭발)
  - files: 파일명·크기·확장자만 메타로 저장 + Blob 보관
  - todo: 체크·텍스트·추가·삭제
  - 블록 순서 변경(드래그) 지원
- **템플릿**: 스키마 필드 묶음 + 블록 프리셋을 한 번에 적용. 최소 3개 기본 제공 — 서로 다른 도메인을 보여주는 것으로:
  - `현장 조사 기본` (사진 + 체크리스트 + 메모)
  - `시설물 점검` (설치일·상태·담당자 + 점검 체크리스트 + 파일)
  - `단순 메모` (텍스트 하나)
  - 템플릿 정의는 `src/templates/*.ts` 데이터 파일로만 존재하고, 코드 분기로 도메인을 구분하지 마라
- 자동 저장. 저장 상태 표시("저장됨 · 방금")

### 7. 레이어 (Phase 1 최소형)
- 레이어 목록 패널: 이름, 표시/숨김 토글, 피처 수, 색상 변경, 순서 변경
- 레이어 생성·삭제·이름 변경
- 각 레이어에 속성 스키마를 정의하는 화면 (필드 추가/삭제/타입 변경)
- Phase 1에서는 **내가 그린 벡터 레이어만**. 파일 업로드와 외부 API는 Phase 2

### 8. 저장
- IndexedDB. 스토어: `projects`, `layers`, `features`, `blobs`
- 쓰기는 디바운스 배치(500ms). 매 키 입력마다 트랜잭션 열지 마라
- 스키마 버전 필드를 두고 마이그레이션 함수를 넣을 자리를 만들어라 (Phase 3 서버 이관 대비)
- GeoJSON 내보내기: 레이어별 / 프로젝트 전체. 속성은 `properties` 에 평탄화하고, 블록은 `_blocks` 키에 JSON 으로 넣되 내보내기 옵션으로 제외 가능하게

### 9. 레이아웃
- **PC**: 좌 레이어 패널(접힘 가능) / 중앙 지도 / 우 정보 페이지 패널(선택 시 슬라이드인)
- **모바일(≤768px)**: 지도 전체화면 + 하단 도구 바. 레이어 패널과 정보 페이지는 바텀시트(3단 스냅: 접힘 / 절반 / 전체)
- 색상·간격은 CSS 변수 토큰으로 정의. 다크모드는 Phase 1 범위 밖이지만 토큰 구조는 대응 가능하게

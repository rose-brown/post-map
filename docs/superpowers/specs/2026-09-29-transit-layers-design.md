## 3. 확인한 GTFS 사실 (2026-09-29 실측)

- 수도권 도시철도: `routes.txt` 의 `route_id` 가 `RR_ACC1_S-1-` 로 시작 (67 노선 패턴, 24 호선명). 운행 9,152 회, 정차 240,894 행.
  `route_type` 은 KTDB 자체 코드 (1 = 도시철도/경전철) — 국제 표준과 다르다 (설명서 4쪽).
- 역: `stops.txt` 의 `RS_ACC1_S-1-` 779 개. 호선별로 따로 있고 이름에 호선이 붙는다 (`시청(1호선)`, `시청(2호선)`).
  기준역 stop: 선릉 `0220`(2호선)·`1023`(수인분당), 여의도 `2527`(5)·`4115`(9), 시청 `0151`(1)·`0201`(2). `시청·용인대` 는 다른 역이다.
- 환승: `transfers.txt` 는 `transfer_type=2` + `min_transfer_time`(초, 60~1020, 중앙값 138). 같은 이름인데 환승 행이 없는 쌍은 양평·신촌·서울(경의선) 뿐 — 실제로 다른 역이다.
- 시각은 `hh:mm:ss`, 24시를 넘는다 (`25:10:00`). `stop_times.txt` 는 따옴표 없는 CSV, 1.4GB.
- 첫 줄에 UTF-8 BOM 이 있는 파일이 있다 (`routes`·`stops`·`trips`·`transfers`).
- `shapes.txt` 없음. 이용 조건 명시 없음.

## 4. 계산 규칙

- **역간 시간**: 같은 운행의 연속 정차 (a→b) 에 대해 `arrival(b) − arrival(a)` 를 모든 운행에서 모아 **중앙값** (방향별 간선). 급행 운행의 간선도 포함한다.
- **환승**: `transfers.txt` 의 간선. 열차 대기시간은 넣지 않는다.
- **기준역까지 시간**: 역 그래프를 뒤집어 기준역 stop 들(이름 괄호 앞이 정확히 일치)에서 다익스트라.
- **도보**: 직선거리 × 1.3 ÷ 72 m/분 (1.2 m/s — 서울교통공사 환승 기준 보행속도).
- **단지 시간**: 2km 이내 모든 역에 대해 `도보 + 역→기준역` 의 최소, 분 반올림. 2km 안에 역이 없으면 키를 저장하지 않는다.
- **역세권**: 가장 가까운 역까지 직선거리 ≤ 500m (보정계수 없음). 거리는 turf 측지 거리 (불변 규칙 3).

## 5. 레이어와 속성

- 호선 레이어 `지하철 <호선>` 24개 — 이름·색은 `scripts/transit/build.ts` 의 `LINES`. 역 포인트만, 속성 `line`(호선)·`stopId`.
- 필터 레이어: `역 500m 이내 (월간선도50)`, `선릉 30분 이내 (월간선도50)`, `선릉 1시간 이내 (월간선도50)`, 여의도·시청 같은 형식.
- 원본: 월간선도50 구간 레이어 5개 + 순위 밖. TOP9 는 사본이라 뺀다.
- 사본 id `{원본id}__{접미사}` (`st500`, `sl30`, `sl60`, `yd30`, `yd60`, `ch30`, `ch60`). 사본은 원본의 속성·블록·제목·좌표를 복사하고 우리 속성을 넣는다.
- 우리 속성 키: `nearestStation`(text), `stationDistance`(number, m), `minSeolleung`·`minYeouido`·`minCityHall`(number, 분).

## 6. 오류 처리

- 모든 계산을 끝낸 뒤에만 쓴다. 기준역 stop 을 못 찾거나 호선이 `LINES` 에 없으면 쓰기 전에 실패한다.
- `--dry-run` 은 레이어별 행 수·기준역별 분포·예시 단지를 리포트하고 쓰지 않는다.

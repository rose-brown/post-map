# 월간선도50 레이어 — 설계

2026-09-27. 브레인스토밍 결과. 구현 계획은 `docs/superpowers/plans/2026-09-27-lead50-layer.md`.

## 1. 목표

아실(asil.kr)처럼 아파트 단지 · 세대수 · 매매 실거래가를 지도에서 본다.
대상은 KB 부동산 데이터허브 `kbstats/lead50` 의 **지역별 시세총액 상위 단지**,
범위는 **서울 25개 구 + 경기 말단 시·군·구**, 지역당 최대 50건.

결과물은 **기존 프로젝트의 일반 레이어**("월간선도50")다. 2026-09-27 에 안양시 50건을 수동 SQL 로
넣어 배포 사이트(`?p=92e81c2e-…`)에서 확인했고, 이 모양을 그대로 자동화한다.
도형은 보통 도형과 똑같이 선택·메모·블록·동심원이 된다.

## 2. 결정

## 3. 사실과 미확인

### 3.1 확인된 사실 (2026-09-27 실호출)

KB 는 모두 **비공식 내부 API** 이고 인증 없이 응답했다.

- **한글 파라미터 키도 인코딩해야 한다.** `curl --data-urlencode` 는 값만 인코딩해 본문 없는 400 이 났다.
  `URLSearchParams` 를 쓴다. 필수값이 빠지면 `{"message":["필수값 [...]이 오류입니다."]}` 로 알려준다.
- 지역 목록: `GET https://data-api.kbland.kr/bfmavm/map/siGunGuAreaNameList?법정동코드=<시도코드>`
  → `[{법정동코드, 시군구명, 하위시군구존재여부, wgs84중심위도, wgs84중심경도}]`.
  서울 `1100000000` 25건. 경기 `4100000000` **55건이 평면 목록**(시와 그 아래 구가 함께).
  **시 코드로 다시 내려가면 경기 전체가 또 온다** — 한 번만 조회하고 `하위시군구존재여부` 로 거른다.
- 지역 순위: `GET https://data-api.kbland.kr/bfmstat/kbleadapt50/areaIndxAndAptPrcIndxAndRankgList`
  필수 7개 `TOP코드, TOP코드명, 기간코드, 기준조건코드, 법정동코드, 변동률여부, 지역명`.
  사용값 `T30 / TOP30 / 24 / A01 / <코드> / 0 / "<시도> <시군구명>"`.
  → `dataBody.data.TOP아파트순위정보.데이터리스트[]`: `순위, 단지기본일련번호, 아파트명, 단지명, 시군구명, 읍면동명,
  세대수값, 준공년월, 평당시세값, 시세총액, 기준년월, KB선도아파트여부`.
  **TOP 코드와 무관하게 최대 50건.** 아파트가 적으면 적게 온다(연천군 13, 가평군 21) — 정상.
  `기준년월` 은 응답 전체에서 하나(202608).
  화성시 동탄·만세·병점·효행구는 **HTTP 500** (`NumberFormatException: "null"`), 화성시 `4159000000` 는 50건.
- 좌표: `GET https://api.kbland.kr/land-complex/complex/brif?단지기본일련번호=<id>`
  → `wgs84위도, wgs84경도, 총세대수, 시군구명, 법정동명, 최소전용면적, 최대전용면적, …`. **지번 없음.**
  표본 6건(강남·연천·안양 50건) 좌표가 모두 해당 지역 안.
- 전국 50 명단 `.../kbleadapt50/aptRankgLeadList` (파라미터 없음) 도 있으나 이 설계는 쓰지 않는다.
- KB 단지별 거래 API(`land-extra/price/v1/api/aptDanjiRealTransPriceChart` 등)는 월 집계뿐.

국토부 (data.go.kr `15126469` "국토교통부_아파트 매매 실거래가 자료", 2026-09-27 실호출):

- `GET https://apis.data.go.kr/1613000/RTMSDataSvcAptTrade/getRTMSDataSvcAptTrade`
  `serviceKey, LAWD_CD(5자리), DEAL_YMD(YYYYMM), numOfRows, pageNo` → 평면 XML.
  정상 `resultCode=000`, `totalCount`, `<item>` 반복. 안양 동안구 2026-08 = 363건 (`numOfRows=1000` 한 페이지).
- item 필드: `sggCd, umdNm, aptNm, jibun, aptDong, excluUseAr, dealAmount("57,200" 만원), dealYear, dealMonth, dealDay,
  floor, buildYear, cdealType, cdealDay, dealingGbn, buyerGbn, slerGbn, rgstDate, estateAgentSggNm, landLeaseholdGbn`.
  **해제 거래는 `cdealType=O`** (동안구 2026-08 에 6건). 단지 식별 코드 필드는 없고 `jibun`("1103-5") 이 있다 — 지번 매칭(D12).
- **`serviceKey` 는 디코딩된 값을 넣어야 한다.** 포털의 Encoding 키(`%xx` 포함)를 `URLSearchParams` 에 그대로 넣으면
  이중 인코딩되어 HTTP 403 `SERVICE_KEY_IS_NOT_REGISTERED_ERROR` 가 난다. 코드는 `decodeURIComponent(MOLIT_KEY)` 로
  두 키 모두 받는다.
- **화성시 거래는 신설 구 코드로만 나온다.** `41590` 은 2025-12·2026-01·2026-08 모두 0건,
  `41591 / 41593 / 41595 / 41597` 은 2026-08 에 85 / 169 / 266 / 139건. 과거 달도 새 코드로 옮겨져 있다.
- `process.loadEnvFile('.env')` 는 현 `.env` 를 문제없이 읽는다.
- 일일 트래픽 한도 10,000 (개발계정, 사용자 확인). 전체 실행 ≈ 870회라 하루에 끝난다.
- KB `GET https://api.kbland.kr/land-complex/complex/main?단지기본일련번호=<id>` → `본번지내용, 부번지내용, 읍면동명, 구주소, 총세대수, wgs84위도, wgs84경도` (전용면적 범위는 없다 — 그래서 `brif` 도 유지).

전체 실행 결과 (2026-09-27, 69 지역):

- 3,288 단지, 실패 지역 0, 좌표 없음 0, 중복 0. 실거래 매칭 **3,208 / 3,288 (97.6%)**.
- **읍·면 지역은 국토부 `umdNm` 이 "가평읍 대곡리"(읍 + 리)** 인데 KB `brif.법정동명` 은 "가평읍" 뿐이다.
  KB `complex/main.구주소`("경기도 가평군 가평읍 대곡리 695") 에서 `읍면동명` 토큰부터 지번 앞까지 이어 맞춘다(`dongOf`).
  고치기 전 미매칭 278 → 고친 뒤 80. 남은 80 은 최근 12개월 무거래(재건축 등)와 KB 지번 없음 9건(개발구역).
- ★: 지역 순위 10 이하에 `icon: 'star'` (사용자 결정). 사용자가 고른 다른 아이콘은 덮지 않고, 밀려나면 ★ 만 뗀다.
- 재실행 보존 확인: 사용자 블록·자유 속성·직접 고른 아이콘(`home`, 순위 1 인데도 유지)이 남고 거래 블록·`recentTrade` 만 갱신.
- 앱 성능 (3,288 도형, Playwright headless, 배포 사이트): 로드→목록 데스크톱 1.8s · iPhone 13 에뮬 1.4s,
  목록 클릭→정보 페이지 0.05s · 0.11s. 실기기는 재지 않았다.
- 국토부 호출은 전체 실행 1회 약 870회 + 페이지, 한도 10,000 안.
- **해제 거래의 "쌍둥이" 비해제 레코드는 실제 거래다 → 해제 레코드만 빼는 지금 처리가 맞다.**
  `cdealType=O` 레코드 상당수에 동·지번·면적·금액·계약일·층이 모두 같은 비해제 레코드가 따로 있다.
  원자료 6개 시군구(강남·송파·서초·동안·동탄·영등포) × 2026-03~08, 15,909건으로 판별했다 (2026-09-27):
  - 해제 699건 중 쌍둥이가 있는 것은 376건(54%) — "모든 해제 거래가 이중 표기된다"면 100% 여야 한다.
  - 쌍둥이 비해제 레코드의 **72% 에 `rgstDate`(소유권이전 등기일)** 가 있다 — 비해제 거래 전체의 등기 비율 71% 와 같다.
    해제된 계약은 등기될 수 없으므로 쌍둥이는 끝까지 간 거래다. 해제 → 같은 조건 재신고(비공개 항목 정정 등)로 본다.
  - 계약→해제 일수 중앙값은 쌍둥이 있음 34일 · 없음 35일로 차이가 없어 이것만으로는 판별되지 않는다.
  - 같은 키의 비해제 레코드가 둘 이상인 경우도 42건 있다 — 같은 날 같은 층·같은 가격의 다른 동 거래일 수 있어, 키가 같다고 중복은 아니다.
  공식 문서(data.go.kr 15126469 기술문서 .hwp, rt.molit.go.kr)는 해제여부 'O' 의 의미만 밝히고 이 쌍은 설명하지 않는다.

### 3.2 미확인

- KB 이용약관 · 자동 수집 허용 여부 · 요청 한도. vworld 와 같이 확인 불가로 남을 수 있다.

### 3.3 명시된 한계

- KB 내부 API 는 예고 없이 바뀔 수 있다. 바뀌면 스크립트가 **실패하고 멈춘다**(부분 기록 없음, 5절).
- 순위에서 빠진 단지는 지도에 남는다 (D6).
- 2026-09-27 수동 입력한 안양시 50건은 **시 단위** 순위였고, 전체 실행에서 모두 동안·만안 구 순위에 들어 흡수됐다.
- 여러 지번에 걸친 단지는 대표 지번 거래만 잡힌다 (샛별한양6 → 1109 만).
- `구주소` 가 개발구역명·산 지번이면 지역명이 어색하다 (`고촌읍 김포신곡6지구 도시개발사업구역`, `초월읍 산`, 2건).
- 쓰기는 원자적이지 않다 — 레이어 → 500행 배치. 중간에 실패하면 일부만 갱신되고, 재실행으로 복구된다(upsert 멱등).
- 실행 중(수집 수 분) 앱에서 같은 단지를 고치면 스크립트의 upsert 가 그 편집을 덮을 수 있다. 실행 중 편집하지 마라.
- 레이어는 이름("월간선도50")으로 찾는다. 사용자가 이름을 바꾸면 다음 실행이 새 레이어와 단지 전체를 중복으로 만든다.
- 순위 밖으로 밀린 단지는 ★ 만 떼고 rank·recentTrade 는 마지막 값으로 남는다 (baseMonth 로 구별).

## 4. 구조

```
scripts/lead50/
  kb.ts        KB 호출 (지역 목록 · 지역 순위 · 단지 상세). 1초 간격, 상세는 캐시.
  molit.ts     국토부 호출 (시군구 × 월). 월 단위 캐시.
  build.ts     순수 함수만. 지역 거르기 · (법정동, 지번) 매칭 · 평형별 최근 거래 · 행 병합 · ★ 관리. 테스트 대상.
  run.ts       진입점. 수집 → build → Supabase upsert → 리포트.
tests/lead50.test.ts
```

- 실행: `node scripts/lead50/run.ts <projectId> [--only <법정동코드,...>] [--dry-run]` (Node 22 타입 제거 실행, 의존성 추가 없음).
  `--only` 는 지역을 좁혀 시범 실행한다 (6절). `--dry-run` 은 수집·매칭·리포트까지만 하고 쓰지 않는다.
- 캐시: `scripts/lead50/.cache/` (gitignore). 단지 상세는 id 별 영구 캐시 — 좌표는 바뀌지 않는다.
  국토부는 `(시군구, 년월)` 별 파일, **최근 2개월은 매번 다시 받는다**(늦은 신고).
- 비밀: `MOLIT_KEY` (신규, `VITE_` 접두사 없음 → 번들 밖). Supabase 는 기존 `VITE_SUPABASE_URL`·
  `VITE_SUPABASE_ANON_KEY` 를 읽고 `x-project-id` 헤더로 RLS 를 통과한다 — 앱과 같은 권한.
- `src/` 는 건드리지 않는다. 도메인 용어(매매·세대 등)는 스크립트와 레이어 데이터에만 있다 (불변 규칙 6).

### 4.2 레이어 스키마 (순서 = 카드 표시 순서)

`recentTrade`(text, 최근 매매) · `rank`(number) · `households`(number, 세대) · `generalHouseholds`(number, 세대) ·
`completion`(text) · `pricePerPyeong`(number, 만원) · `marketCap`(text) · `exclusiveArea`(text) ·
`region`(text) · `baseMonth`(text) · `kbComplexId`(text).

안양 수동 입력분과 같은 키다(`recentTrade` 만 추가). 값이 없으면 키를 넣지 않는다 (PRD 4.3).

`recentTrade` 예: `84㎡ 15.1억 · 26.08 · 12층`. 블록 한 줄 예: `59㎡  12.3억  26.07  8층`.

## 5. 오류 처리

- **쓰기 전에 전부 모은다.** 수집·매칭 중 실패하면 Supabase 에 아무것도 쓰지 않고 종료 코드 1.
- 예외: 지역 1개가 500 이면 그 지역만 리포트에 올리고 계속한다(화성 신설 구 같은 서버 측 결함).
  대체 규칙(D4)에 없는 새 500 이 나오면 사람이 보도록 리포트 맨 위에 둔다.
- 국토부 한도 초과·인증 실패는 즉시 종료.
- 리포트(표준 출력): 지역 수·단지 수·좌표 실패·매칭 실패(단지명 목록)·신규/갱신 수.

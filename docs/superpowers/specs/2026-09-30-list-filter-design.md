# 목록 필터 설계 (Phase 2-B 의 F-71 만 먼저)

- 날짜: 2026-09-30
- 근거: PRD F-71, `docs/prompts/03-Phase2-...` 5절(테이블 뷰) 중 필터만. 동기는 `docs/book/Location.json`(입지 체크리스트)으로
  월간선도50 3,288 단지를 좁혀 보는 것 — 점수 레이어 대신 **원시 속성에 조건을 거는** 쪽을 사용자가 골랐다.
- Phase 2 는 2-A ~ 2-E 로 쪼개 진행한다 (`2026-09-23-phase2a-geo-ops-undo-design.md`). 이 문서는 2-B 의 일부다.
  2-A 는 설계·계획만 있고 구현되지 않았다 — 이 작업은 2-A 에 의존하지 않는다.

## 1. 목표 (완료 기준)

1. 목록 패널 헤더의 `필터` 로 조건을 추가·수정·삭제할 수 있다. 조건은 AND.
2. 숫자 필드는 `이상 / 이하 / 사이`(경계 포함), 텍스트 필드는 `포함`(대소문자·앞뒤 공백 무시).
3. 걸러진 도형은 목록과 지도(Terra Draw 도형·아이콘) 양쪽에서 사라진다.
4. 필터가 있으면 개수가 `통과 / 필터 전` 으로 보이고, 0건이면 `조건에 맞는 도형이 없습니다 · 필터 지우기`.
5. 모바일 바텀시트에서도 같은 조작이 되고(44px), 시트를 닫아도 필터가 켜져 있음이 하단 `목록` 버튼에 보인다.
6. 월간선도50 순위 구간 레이어 6개만 켜고 `총세대수 ≥ 1000` · `역까지 ≤ 800` 을 걸면 목록 개수 = 데이터로 직접 센 값, 지도는 같은 도형만 보인다 (5절 2).

## 2. 확정된 결정

| # | 결정 | 이유 |
|---|---|---|
| D1 | 필터 상태는 **스토어에만** (`filters`). 새로고침하면 사라진다. 서버·localStorage 에 두지 않는다 | 탐색 도구다. 조건 저장은 이번 범위 밖(사용자 선택). 필요해지면 localStorage 로 올리기 쉽다 |
| D2 | 대상은 **보이는 레이어 전체**. 필드는 보이는 레이어 스키마의 number·text 필드를 key 로 합친 것, 같은 key 면 첫 레이어 정의 | 사용자 선택. 실제 용도는 순위 구간 레이어 6개(스키마 동일)를 켜고 거는 것 |
| D3 | 조건 필드 값이 없는 도형은 **걸러진다** | 2km 안에 역이 없는 434 단지(HANDOFF 기준, 재집계 안 함)는 `역까지 ≤ 800` 에서 빠지는 게 맞다 |
| D4 | 값이 비었거나 숫자가 아닌 조건, `사이` 의 한쪽만 입력된 조건은 **무시** | 입력 도중 0건으로 깜빡이지 않게. `사이` 를 반쪽 `이상/이하` 로 해석하는 규칙을 두지 않는다 |
| D5 | 조건 필드가 보이는 레이어에 없으면 그 조건은 **"적용 안 됨"** 으로 흐리게 두고 판정에서 뺀다. 지우지 않는다 | 판정에 넣으면 전부 0건이 돼 원인이 안 보인다. 레이어를 다시 켜면 되살아난다 |
| D6 | 표시용 필드 정의(label·unit)는 **전체 레이어**에서, 판정용 필드 목록은 **보이는 레이어**에서 찾는다 | D5 의 조건도 제목을 그려야 한다 |
| D7 | **선택된 도형은 지도에서 필터를 건너뛴다** (레이어 숨김은 건너뛰지 않는다): `보이는 레이어 AND (통과 OR 선택됨)`. 목록에는 예외가 없다 | 없으면 필터 중 새로 찍은 점이 `finish`→`select` 직후 동기화 이펙트에 지워진다. 선택 중엔 목록 대신 정보 페이지가 떠서 목록 예외는 필요 없다 |
| D8 | 동심원(`rings`/`ringLabels`)에는 필터를 걸지 않는다 | 이 소스는 지금도 레이어 숨김을 보지 않는다(기존 동작). 숨김·필터를 같이 맞추는 건 별도 작업. 월간선도50 에는 동심원이 없다 |
| D9 | 포인트 크기(`sizeRatios`)는 필터와 무관하게 전체 도형 기준 | 필터로 점 크기가 다시 매겨지면 비교가 안 된다 |
| D10 | 필터 버튼은 **필드도 없고 조건도 없을 때만** 비활성 | 조건이 남은 채 레이어를 다 끄면 지울 길이 없어진다 |
| D11 | 연산자는 PRD F-71 보다 좁힌다 (`=`·`>`·날짜·select 없음) | 대상 레이어 필드가 number·text 뿐. 테이블 뷰(2-B 나머지) 때 넓힌다 |

## 3. 구조

### 3.1 `src/filter.ts` (순수 함수, 도메인 용어 없음)

```ts
export type FilterOp = 'gte' | 'lte' | 'between' | 'contains'
export interface FilterCond {
  id: string
  key: string
  op: FilterOp
  /** 입력칸 문자열 그대로. 해석은 matches 가 한다. between 은 [min, max] */
  value: string | [string, string]
}
/** number·text 스키마 필드를 key 로 합친다. 같은 key 면 먼저 나온 레이어 정의. */
export function filterFields(layers: Layer[], opts: { visibleOnly: boolean }): PropertySchemaField[]
/** 판정에 쓰일 조건만: 값이 해석되고(D4) 필드가 fields 에 있는 것(D5). */
export function activeConds(conds: FilterCond[], fields: PropertySchemaField[]): FilterCond[]
/** 모든 조건 AND. 키가 없으면 false. conds 가 비면 true. */
export function matches(feature: Feature, conds: FilterCond[]): boolean
```

- 숫자 해석: 쉼표·공백 제거 후 `Number`, `NaN` 이면 무효.
- 값은 입력 문자열로 들고 있는다 — 숫자로 바로 바꾸면 `1,` 같은 입력 중간 상태를 잃는다.

### 3.2 스토어 (`src/store/useStore.ts`)

`filters: FilterCond[]` · `setFilters(filters)`. `repo.ts` 를 거치지 않는다 (D1).
zustand 함정대로 셀렉터 안에서 파생하지 않고, 소비하는 쪽이 `useMemo` 로 `activeConds` 를 만든다.

### 3.3 적용 지점

| 곳 | 지금 | 바뀌는 것 |
|---|---|---|
| `ui/FeatureList.tsx` `rows` | 보이는 레이어 + `!derivedFrom` | `&& matches(f, active)`. 필터 전 개수도 같이 계산 |
| `map/MapView.tsx` 동기화 이펙트 (`drawable`) | `!derivedFrom && !hidden` | `&& (matches(f, active) \|\| f.id === selectedId)`. 의존성에 `filters`·`selectedId` 추가 |
| `map/MapView.tsx` `pointIcons` 이펙트 (`wanted`) | 아이콘 있음 + 보이는 레이어 | 같은 조건 추가 |

걸러진 도형은 숨긴 레이어와 같은 경로(`syncedIds` 고아 제거 → `removeFeatures` 배치 1회)로 빠진다.
`updateFeatureProperties` 는 부르지 않는다. 선택이 바뀔 때마다 이펙트가 돌지만 추가·제거가 없으면 판정 계산뿐이다.

## 4. UI

`FeatureList` 는 PC 우측 패널과 모바일 바텀시트 `목록` 양쪽에 같은 컴포넌트로 들어간다(`App.tsx`).
그래서 필터 UI 를 `FeatureList` 헤더에 붙이면 둘 다 덮인다. 새 컴포넌트는 `ui/FilterBar.tsx` 하나.

```
기록  812 / 3,288          [필터 2] [최근순][이름순]
┌──────────────────────────────────────────────┐
│ [총세대수 ▾] [이상 ▾] [1000    ] 세대      ✕ │
│ [역까지   ▾] [이하 ▾] [800     ] m         ✕ │
│ + 조건 추가                        모두 지우기 │
└──────────────────────────────────────────────┘
```

- `필터` 는 헤더 아래 조건 영역을 접고 편다(모달 아님). 조건이 있으면 강조 + 개수. 접어도 적용된다.
- 조건 한 줄: 필드 · 연산자(필드 타입에 맞는 것만) · 값(`사이` 는 두 칸) · 단위(`field.unit`) · ✕.
  필드를 바꾸면 타입이 다를 때 연산자와 값을 초기화한다.
- `+ 조건 추가` 는 첫 필드로 빈 조건을 만든다. `모두 지우기` 는 `filters = []`.
- 개수: 필터가 없으면 지금처럼 숫자 하나.
- "적용 안 됨" 조건(D5)은 흐리게, 라벨은 D6 의 전체 레이어 정의로.
- 모바일(`embedded`): 입력·버튼에 `touch-target`, 입력 글자 16px (iOS 가 16px 미만 입력칸에서 확대한다).
- 하단 `목록` 버튼(`App.tsx`)에 활성 조건이 있으면 점 표시.

## 5. 테스트

`tests/filter.test.ts` (`node --test tests/filter.test.ts`):

- `gte`·`lte`·`between` 경계 포함, 키 없음 → false, 빈 conds → true
- 빈 값·숫자 아님·`between` 반쪽 → `activeConds` 에서 빠짐, 쉼표 입력 `1,000` 해석
- `contains` 대소문자·앞뒤 공백 무시, 숫자 값에 `contains` 는 문자열로 비교
- `filterFields`: key 병합·첫 정의 우선, number·text 외 제외, `visibleOnly` 에서 숨긴 레이어 제외
- 필드가 보이는 목록에 없는 조건은 `activeConds` 에서 빠짐

브라우저 (Playwright, `npm run dev`, 월간선도50 프로젝트):

1. 순위 구간 레이어 6개만 켜고 `총세대수 ≥ 1000`·`역까지 ≤ 800` → 목록 개수 = 스토어 데이터로 직접 센 값.
   스토어는 콘솔에서 `await import('/src/store/useStore.ts')` 로 같은 인스턴스를 얻을 것으로 **추정** —
   안 되면 전역을 새로 노출하지 않고 Supabase 데이터를 스크립트로 읽어 센다.
2. 지도 점은 직접 세지 않는다 — 지도·Terra Draw 가 전역에 없고 확인용으로 노출하지 않는다. 필터 전후 스크린샷 비교 +
   목록 통과 단지 3개가 지도에 있고 걸러진 단지는 없는지로 대신한다.
3. ★ 아이콘도 같이 걸러진다.
4. 필터 중 새 점: 선택 중엔 보이고, 선택을 풀면 사라진다 (D7).
5. 레이어를 끄면 조건이 "적용 안 됨", 켜면 되살아남. 전부 끄고도 필터를 열어 지울 수 있다 (D10).
6. 390px 폭 바텀시트에서 조작, 시트를 닫으면 `목록` 버튼에 점.

스크린샷 `docs/screenshots/filter-*.png`. `npm test`·`npm run typecheck`·`npm run build` 통과.

## 7. 후속: 입지 체크리스트 데이터 추가 (별도 스펙으로)

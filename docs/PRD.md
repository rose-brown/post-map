# PRD — 범용 지도 편집 플랫폼

> 전제: `00-공통-컨텍스트.md` 의 기술 스택과 불변 규칙은 확정 사항으로 두고 재논의하지 않는다.
> 이 문서에서 숫자로 적힌 외부 API 사실은 **본문에 출처가 달린 것만 확인된 값**이다. 나머지는 `(확인 필요: 출처)` 로 표시했다.
>
> **3장 표기 변경**: `01` 프롬프트는 기능당 세로 표를 지정했으나 기능이 40개를 넘어 세로 표로는 읽기 어렵다.
> 지정된 7개 항목(기능ID·이름·입력·동작·출력·예외·Phase)을 그대로 **열**로 쓰는 가로 표로 바꿨다. 항목 누락은 없다.

---

## 1. 제품 정의

**한 문장** — 사용자가 레이어와 속성 스키마를 직접 정의해서, 지도 위에 그린 도형마다 정보 페이지를 붙이고 공간 연산을 걸 수 있는 웹 기반 지도 편집 도구.

**해결하는 문제**

현장 정보를 지도에 기록하려는 사람에게 지금 선택지는 둘뿐이다. 카카오맵·네이버지도의 "내 장소"는 핀에 메모 한 줄이 한계고 도형을 그릴 수 없다. QGIS는 다 되지만 설치형 데스크톱이라 현장에서 못 쓰고 학습비용이 크다. **도형을 그릴 수 있으면서, 도형마다 구조화된 속성과 자유 메모를 함께 갖고, 모바일 브라우저에서 바로 열리는 도구**가 그 사이에 없다.

**명시적 비목표 (Non-goals)**

| 하지 않는 것 | 경계 |
|---|---|
| QGIS 대체 | 래스터 분석·지오프로세싱 툴박스·좌표계 정의 편집·인쇄 레이아웃 없음. 공간연산은 buffer / union / intersect / difference / 면적 / 길이로 **고정**한다 |
| 카카오맵·네이버지도 대체 | 국내 POI 품질, 실시간 교통, 대중교통 안내로 경쟁하지 않는다. 배경지도·검색은 공공 API 수준으로 충분하다고 본다 |
| 네이티브 앱 | 반응형 웹만. 앱스토어 배포·백그라운드 위치추적·오프라인 지도 캐시 없음 |
| 실시간 공동편집 | Phase 3의 공유는 권한 기반 접근이지 동시 커서·CRDT 병합이 아니다 |
| 대용량 GIS 서빙 | 레이어당 피처 수 상한을 두고 초과 시 거부한다. 벡터타일 서빙은 Phase 4 이후 재검토 |

**제품의 정체성을 결정하는 한 가지** — 도형과 속성은 **사용자 소유 데이터로 영구 저장된다.** 이 전제 때문에 응답 저장을 금지하는 외부 API를 쓸 수 없고, 그것이 8장의 가장 큰 미결 항목을 만든다.

## 2. 사용자와 시나리오

같은 도구가 서로 다른 용도를 **템플릿으로만** 흡수하는지 보이는 것이 이 장의 목적이다. 아래 세 시나리오에서 도메인 분기 코드는 하나도 생기지 않아야 한다.

### 2.1 부동산 임장자 — 개인, 모바일 주 사용

> 주말에 매물 5곳을 돌며 현장 기록을 남기고, 집에 와서 PC로 비교한다.

1. 모바일에서 프로젝트 `2026 봄 강남 임장` 을 연다
2. 상단 검색창에 `역삼동 737` 입력 → 후보에서 첫 번째 선택
3. 지도가 그 좌표로 이동하고 point 가 생기며 정보 페이지가 바텀시트로 올라온다
4. 템플릿 `현장 조사 기본` 탭 → 속성 4개(방 수·면적·가격·조사일)와 블록 3개(제목 / 메모 / 체크리스트)가 한 번에 붙는다
5. 가격 `35000` 입력 → `35,000 만원` 으로 천단위 구분과 단위가 표시된다
6. 체크리스트 `수압 확인` 체크, 카메라로 사진 4장 추가 → 갤러리 블록에 들어간다
7. 바텀시트를 내리고 point 를 다시 탭 → `동심원` → 기본값 `500 / 1000 / 2000m` 확정 → 링 3개와 반경 라벨이 그려진다
8. 5곳 반복. 지하철에서 탭을 닫아도 IndexedDB에 남아 있다
9. 집에서 PC로 접속 → 테이블 뷰 → `가격` 오름차순 정렬 → 행 클릭 시 지도에서 해당 핀 선택 *(Phase 2)*

### 2.2 시설물 점검 담당자 — 기업, PC + 현장 태블릿

> 설비 200개 위치가 담긴 SHP를 올리고 분기 점검 결과를 기록한다.

1. PC에서 `설비대장.zip`(SHP, EPSG:5186)을 지도 위로 드래그앤드롭 *(Phase 2)*
2. `.prj` 가 읽혀 중부원점으로 인식되고, 미리보기 좌표가 한반도 범위에 드는지 확인 후 `적용`
3. DBF 속성이 깨져 보여 인코딩을 `CP949` 로 전환 → 한글 설비명 정상 표시
4. 컬럼 스캔으로 스키마 자동 생성(`설치일`→date, `용량`→number, `담당자`→text). `용량` 단위에 `kW` 직접 입력
5. 레이어에 템플릿 `시설물 점검` 적용 → 점검 체크리스트 프리셋이 붙는다
6. 태블릿을 들고 현장에서 피처를 탭 → 체크 기록, 파손 사진 첨부
7. PC에서 테이블 뷰 → `점검상태 = 이상` 필터 → 12건 → 선택 행만 CSV 내보내기 *(Phase 2)*

### 2.3 상권 조사자 — 소규모 팀, PC 주 사용

> 후보 점포 3곳의 상권 범위를 그려 겹치는 구역을 찾는다.

1. 후보 3곳을 검색으로 찍는다
2. 각 point 에 동심원 `300 / 500m` 을 건다
3. 도보 가능 범위를 따라 polygon 을 직접 그리고, 꼭짓점을 끌어 골목 경계에 맞춘다
4. 두 polygon 선택 → `교차` → 새 피처 생성, 정보 페이지에 `생성 방식: intersect(F-04, F-07)` 기록 *(Phase 2)*
5. 면적이 `1,240㎡ · 375평` 으로 자동 표시된다 *(Phase 2)*
6. GeoJSON 으로 내보내 팀에 전달 → Phase 3부터 링크 공유로 대체

## 4. 데이터 모델

### 4.1 엔티티

```
Project 1 ──< Layer 1 ──< Feature
                            │
                            ├── properties : 스키마 필드 + 자유 필드 (하이브리드)
                            └── blocks     : 자유 블록 배열
Layer 1 ──< PropertySchemaField
Template  : 독립 엔티티 (스키마 필드 묶음 + 블록 프리셋), 레이어에 적용
Blob      : Feature 의 gallery·files 블록이 참조
```

### 4.2 필드 정의

**Project**

| 필드 | 타입 | 제약 |
|---|---|---|
| `id` | uuid | PK |
| `name` | text | not null |
| `description` | text | |
| `initialView` | json | `{ lng, lat, zoom, bearing, pitch }` |
| `ownerId` | uuid | Phase 3부터 not null, FK→auth.users |
| `schemaVersion` | int | 마이그레이션용. Phase 1 = 1 |
| `createdAt` / `updatedAt` | timestamptz | |

**Layer**

| 필드 | 타입 | 제약 |
|---|---|---|
| `id` | uuid | PK |
| `projectId` | uuid | FK→Project, **index** |
| `name` | text | not null |
| `kind` | enum | `vector` \| `file` \| `tile` \| `api` |
| `visible` | bool | default true |
| `order` | int | 프로젝트 내 정렬. `(projectId, order)` index |
| `style` | json | `{ color, opacity, strokeWidth, pointRadius }` |
| `schema` | json | `PropertySchemaField[]` |
| `sourceMeta` | json | 업로드 원본: `{ fileName, originalCrs, encoding, uploadedAt }` |
| `locked` | bool | default false |

**Feature**

| 필드 | 타입 | 제약 |
|---|---|---|
| `id` | uuid | PK |
| `layerId` | uuid | FK→Layer, **index** |
| `geometry` | GeoJSON json → PostGIS `geometry(Geometry, 4326)` | not null, **GIST index**(Phase 3) |
| `title` | text | |
| `properties` | json(jsonb) | 스키마 필드 + 자유 필드. **jsonb GIN index**(Phase 3) |
| `blocks` | json(jsonb) | 블록 배열. 조회·필터 대상 아님 |
| `derivedFrom` | json | `{ op: 'buffer'\|'union'\|'intersect'\|'difference'\|'ring', sourceIds: uuid[], params: {} }` |
| `parentId` | uuid \| null | 동심원 링 → 중심 point. 부모 삭제 시 cascade |
| `createdAt` / `updatedAt` | timestamptz | |

**PropertySchemaField**

`{ key, label, type, unit?, required?, options? }` — `key` 는 레이어 내 유일.

### 4.3 속성 타입 시스템

| type | 저장 형태 | 입력 UI | 필터 연산자 |
|---|---|---|---|
| `text` | string | 한 줄 입력 | `포함` `일치` `시작` `비어있음` |
| `number` | number | 숫자 입력 + 단위 접미사, 천단위 구분 표시 | `=` `>` `<` `>=` `<=` `between` |
| `date` | ISO 8601 string (`YYYY-MM-DD`) | 날짜 선택기 | `=` `기간(between)` `이전` `이후` |
| `select` | string (options 중 하나) | 드롭다운 | `in` `not in` |
| `multiselect` | string[] | 다중 선택 칩 | `contains any` `contains all` |
| `boolean` | bool | 토글 | `=` |
| `url` | string | 입력 + 링크 열기 | `포함` `비어있음` |
| `phone` | string | 입력 + 통화 링크 | `포함` `비어있음` |

값이 없으면 키를 저장하지 않는다(`null` 을 넣지 않는다). 필터의 `비어있음` 은 키 부재와 빈 문자열을 모두 참으로 본다.

### 4.4 로컬(IndexedDB) ↔ 서버(PostGIS) 대응

| IndexedDB 스토어 | 키 / 인덱스 | PostgreSQL 테이블 | 전환 시 달라지는 점 |
|---|---|---|---|
| `projects` | key `id` | `projects` | `ownerId` 추가, RLS 적용 |
| `layers` | key `id`, index `projectId` | `layers` | `schema` jsonb 유지 |
| `features` | key `id`, index `layerId`, `parentId` | `features` | `geometry` json → `geometry(Geometry,4326)` + GIST. `properties` → jsonb + GIN |
| `blobs` | key `id`, index `featureId` | Supabase Storage | DB가 아니라 객체 스토리지로. `blocks` 안의 참조는 key 문자열로 유지되므로 블록 구조는 안 바뀐다 |
| `meta` | key `schemaVersion` | — | 마이그레이션 완료 플래그 |

**마이그레이션 원칙** — `schemaVersion` 을 Project 와 `meta` 양쪽에 두고, 버전별 업그레이드 함수를 순차 적용한다. Phase 3 이관은 **복사**이지 이동이 아니다. 이관 실패 시 로컬 데이터를 지우지 않는다(F-81).

## 7. Phase 계획

| Phase | 범위 | 완료 기준 | 새로 필요한 키 |
|---|---|---|---|
| **1** | 작도·동심원·검색·정보 페이지·최소 레이어·IndexedDB·GeoJSON 내보내기 | `02` 문서의 완료 기준 10개 | `VITE_VWORLD_KEY`(타일), `VITE_GEOCODER_KEY`(공공데이터포털) |
| **2** | 파일 업로드·좌표계 변환·공간연산·배경지도 확장·경로·테이블 뷰·Undo/Redo | `03` 문서의 완료 기준 8개 | 경로 API 키 (**D-1 확정 후**) |
| **3** | Supabase + PostGIS, 인증, 팀 공유·권한, Edge Function 프록시 | 로컬 데이터가 서버로 이관되고 권한별 접근이 동작 | Supabase 프로젝트 |
| **4** | 공공데이터 연동, 등시선, 다대다 행렬 | (미작성 — `05` 프롬프트 필요) | data.go.kr 데이터셋별 키 |

**Phase 간 마이그레이션 지점**

가장 큰 단절은 **Phase 2→3 의 로컬→서버 이관**이다. 세 가지를 Phase 1부터 준비한다.

1. `schemaVersion` 필드와 빈 마이그레이션 함수 자리 (Phase 1)
2. Blob 참조를 **key 문자열**로 저장 — IndexedDB든 Supabase Storage든 블록 구조가 바뀌지 않게 (Phase 1)
3. API 키를 Vite dev 프록시 뒤에 두기 — Phase 3에서 Edge Function 으로 **경로만** 바꾸면 되게 (Phase 1)

또 하나의 단절은 **경로 API 확정(D-1)** 이다. 이것이 Phase 2를 막는다.

## 8. 결정이 필요한 항목

### D-1. 경로 API 제공자 — **Phase 2 전체를 막는다. 가장 시급.**

이 항목의 1순위 기준은 요금이 아니라 **응답 결과를 저장해도 되는가**다. 조사 결과 **국내 상용 3사 모두 영구 저장을 허용하지 않는다.**

| 제공자 | 응답 저장 허용 | 무료 제공량 | 근거 |
|---|---|---|---|
| **카카오모빌리티** 길찾기 | **불가.** 응답 원본과 가공 데이터를 기기·서버에 저장 금지. **임시 캐싱도 금지** | 대중교통·도보·자전거 각 1,000건/일 (확인 필요: 시행일 기준 공지) | 카카오 데브톡 공식 답변 |
| **네이버 클라우드** Directions | **불가.** 결과를 별도 저장하거나 DB화 금지. 반환값은 자사 서비스에서 1회 사용만 허용 | (확인 필요: ncloud 요금표) | NCP AI·Naver API 서비스 이용약관 |
| **TMAP** | **조건부.** 저장은 되나 **저장 후 24시간 이상 사용 불가** | 경로안내 1,000건/일, 지오코딩 20,000건/일, 지도표시 100,000건/일 | TMAP API 무료체험 약관 |
| **자가호스팅** (Valhalla / OSRM / ORS) | **가능.** 엔진은 MIT 등 오픈소스, 데이터는 OSM ODbL — 저장·재사용에 약관 제약 없음 | 서버 비용만 | Valhalla 저장소·문서 |

**이 표가 뜻하는 것** — `소요시간을 피처 속성으로 영구 저장` 기능(F-41)은 **국내 상용 API로는 성립하지 않는다.** 선택지는 셋이다.

| 안 | 내용 | 트레이드오프 |
|---|---|---|
| **A. 상용 API + 저장 포기** | 카카오·네이버·TMAP 중 하나. `canPersistResults = false` 경로로 동작, 경로는 세션 메모리에만 | 구현 가장 빠름. 국내 도로 품질 최상. 그러나 F-41이 사라지고 화면 이탈 시 값이 증발 — 제품 정체성("영구 저장")과 정면 충돌 |
| **B. 자가호스팅 (Valhalla/OSRM)** | OSM 데이터로 라우팅 엔진 직접 운영 | F-41·F-43(등시선)·F-44(행렬) 전부 성립. 폐쇄망 대응도 자동 해결. 대신 서버 운영 비용·OSM 한국 도로 데이터 품질 리스크·초기 구축 공수 |
| **C. TMAP 24시간 캐시** | TMAP 사용, 소요시간을 24시간 TTL 캐시로만 보관하고 만료 시 재조회 | 상용 품질 + 부분적 저장. 그러나 "지난 분기 조사 결과"를 다시 보는 순간 값이 없다. TTL 관리 복잡도 추가 |

**권고: B(자가호스팅)를 기본으로 하되, Phase 2 착수 전 A를 병행 제공하는 방향.**
근거 — 이 제품에서 소요시간은 "조회하고 버리는 값"이 아니라 "매물 비교의 축"이다. A를 고르면 2.1 시나리오의 비교 기능이 무너진다. B의 비용은 지도 서버 1대 수준이고, D-2(등시선)까지 한 번에 해결된다.

**확인해야 할 것**
- 각 제공자에게 **직접 서면 확인**. 위 근거 중 카카오 건은 공식 약관 문서가 아니라 데브톡 담당자 답변이다
- OSM 한국 도로망 커버리지가 실용 수준인지 실제 경로로 검증 (확인 필요: 직접 테스트)
- ODbL 의 share-alike 가 "저장한 소요시간을 포함한 사용자 데이터 내보내기"에 어떻게 걸리는지 법무 확인 (확인 필요: 출처)

**기한: Phase 2 착수 전.**

### D-2. 등시선 — 외부 API vs 자가호스팅

D-1 과 묶인다. D-1에서 B를 고르면 Valhalla 가 등시선을 내장 제공하므로 **자동으로 해결된다.** A·C를 고르면 등시선 전용으로 별도 제공자를 찾아야 하고, 저장 문제가 다시 반복된다.
**기한: Phase 4 착수 전. 단 D-1과 함께 결정하는 것이 합리적이다.**

### D-3. SHP 파싱 위치 — 브라우저 vs 서버

| 안 | 트레이드오프 |
|---|---|
| **브라우저 (shpjs + Web Worker)** | 서버 불필요, Phase 2에서 바로 가능. 대용량(수백 MB)에서 메모리 한계, CP949 디코딩을 직접 처리해야 함 |
| **서버 (Phase 3 이후 Edge Function)** | 대용량·인코딩 안정적. 그러나 Phase 2에는 서버가 없으므로 이 기능이 Phase 3으로 밀린다 |

**권고: 브라우저 + 50MB 상한.** 상한 초과분은 Phase 3에서 서버 경로를 추가한다.
**기한: Phase 2 착수 전.**

### D-4. 대용량 렌더링 전환 시점 — GeoJSON → 벡터타일

피처 수가 얼마를 넘으면 PostGIS 벡터타일 서빙으로 갈 것인가. 6장에서 레이어당 50,000개를 상한으로 **가정**했으나 실측 없이 정한 숫자다.
**권고: Phase 2 완료 시 실측하고 그 숫자로 6장을 갱신한다.**
**기한: Phase 3 설계 전.**

### D-5. VWorld 오픈API 이용약관 (신규 — `00` 의 미해결 사항)

`00` 문서 기준으로 vworld.kr 이 크롤링을 막아 **자체 오픈API 이용약관과 검색 API 2.0 스펙을 직접 읽지 못한 상태**였다. 배경지도 타일이 Phase 1의 완료 기준 1번이므로 이것이 미확인인 채로 Phase 1이 끝날 수 없다.

**해소된 것 — WMTS 타일 스펙** (2026-09-21, 발급키로 `WMTSCapabilities.xml` 을 직접 받아 확인. 문서 추론 아님)

`https://api.vworld.kr/req/wmts/1.0.0/{key}/WMTSCapabilities.xml` 의 `ResourceURL` 기준:

| 항목 | 확인값 |
|---|---|
| 타일 URL | `https://api.vworld.kr/req/wmts/1.0.0/{key}/{layer}/{z}/{y}/{x}.{ext}` — **z/y/x 순서** (`{TileMatrix}/{TileRow}/{TileCol}`) |
| 배경 레이어 | `Base` · `midnight` · `white` · `Hybrid` = png, `Satellite` = jpeg |
| 타일 행렬 | `GoogleMapsCompatible` (EPSG:3857, 256px) — MapLibre 래스터 소스에 그대로 들어간다 |
| 줌 범위 | 최대 19. z20 은 `ExceptionReport / InvalidParameter` |
| 위성 라벨 | `Satellite` 에는 지명이 없다. `Hybrid` 를 위에 겹쳐야 한다 |
| 인증 | Referer 없이도, `http://localhost` Referer 로도 타일 200. 도메인 검증이 타일 요청을 막지는 않았다 |

**아직 확인 못한 것**: 이용약관 원문, 상업적 이용 가능 여부, 쿼터·요청 한도, 포털 발급 키와 vworld.kr 직접 발급 키가 같은 엔드포인트인지, 검색·지오코딩 API 2.0 파라미터 스펙.
**기한: Phase 1 착수 전.** (확인 필요: vworld.kr 원문)
